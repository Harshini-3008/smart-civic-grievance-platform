# CivicPulse — Smart Civic Grievance Platform

CivicPulse lets residents report local issues, follow progress, and upvote community reports. Authorities can review reports and update their status.

**Repository:** [Harshini-3008/smart-civic-grievance-platform](https://github.com/Harshini-3008/smart-civic-grievance-platform)

## Run locally

### Requirements

- Node.js 20 or newer (Node.js 22 LTS recommended)
- npm (included with Node.js)

### VS Code

1. Clone the repository and open the `smart-civic-grievance-platform` folder in VS Code (the folder containing `package.json`).
2. Open **Terminal → New Terminal** and run:

   ```powershell
   npm install
   npm run dev
   ```

3. Open [http://localhost:3000](http://localhost:3000). The API health check is at [http://localhost:3000/api/health](http://localhost:3000/api/health).

To run without the file watcher, use `npm start`. You can also press **F5** in VS Code to start the server with the Node debugger.

The SQLite database and uploaded images are created automatically. Demo data is seeded on the first start. New account details are held as a password hash in SQLite while OTP verification is pending, then the verified account, reports, photos, votes, and authority status changes are saved in the database/files. Restarting the local server does not erase them.

## Publish a public demo

The repository includes a Render Blueprint in `render.yaml` so the frontend and API are deployed together. Once these changes are pushed to GitHub, you can [deploy the blueprint to Render](https://render.com/deploy?repo=https%3A%2F%2Fgithub.com%2FHarshini-3008%2Fsmart-civic-grievance-platform) or follow these steps:

1. Push the repository to GitHub.
2. In Render, choose **New → Blueprint**, connect the GitHub repository above, and deploy the `render.yaml` blueprint.
3. Render builds the app and gives the service a public `onrender.com` URL. Share that URL to let others view and try the demo; keep the repository link above as the source-code link.

Render's free web services may sleep when idle, and this demo's SQLite database and uploaded files are ephemeral on the free plan. Seed data is restored when the service starts; use persistent storage and replace demo OTP/auth settings before any production use.

## Project layout

- `server.js` — Express app, static frontend, API routes, and health endpoint
- `public/index.html` — CivicPulse frontend
- `db.js` — SQLite schema and demo seed data
- `routes/` — Authentication, reports, authority, and user API routes
- `middleware/auth.js` — JWT authentication and authority-role checks

## Configuration

`PORT` is provided automatically by Render and defaults to `3000` locally. `JWT_SECRET` is generated by the Render Blueprint; locally, the app uses a development-only fallback. `DATABASE_PATH` can optionally point SQLite to a different file; otherwise the database is `civicpulse.db` in the project folder.
